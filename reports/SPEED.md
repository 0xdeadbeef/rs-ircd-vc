## Method

* One case at a time, one thread, no `RUSTFLAGS`, no `target-cpu=native`: the numbers describe the default build, which is what ships.
* Each round times a fixed number of operations after a warm-up pass. The harness folds a checksum so the optimiser cannot delete the work.
* Allocation is included wherever the real path allocates: parsing builds a `Message`, while serialisation reuses one buffer.
* This is not a replacement for `cargo bench --bench dispatch` and friends, which use criterion and report confidence intervals. It exists so a report can be generated from a single command with the environment fingerprinted.

## Limits

* Absolute values mean little across machines; compare two runs of this binary on the same host, or the same case across revisions.
* A debug build is not representative. Generate reports with `--release`, which the profile line above records.
* These cases measure library functions in isolation. They say nothing about syscall cost, lock contention or fan-out under a real client load; `BENCH` on a live server and the fan-out criterion bench cover those separately.
